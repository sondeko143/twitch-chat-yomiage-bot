# tcyb read-chat の視聴者一覧ログ（monitor の周期取得を記録する）

## 問題

`read-chat` は `monitor.enabled = true` のとき視聴者一覧を周期取得して配信口へ流しているが、どこにも記録していない。配信中の視聴者の推移をファイルに残すには、従来どおり `show-chatters --interval N >> chatters.csv` を別プロセスで並走させるしかない。

- 同じ Get Chatters を 2 プロセスが別々に叩き、API 呼び出しが二重になる。
- 同じトークンストアを 2 プロセスがそれぞれリフレッシュしうる。
- 記録のためだけに `read-chat` と別の常駐を 1 つ余計に起動・停止する運用になる。

## ゴール

- `read-chat` が、視聴者一覧の周期取得の結果を、設定で指定したファイルへ `show-chatters` と同じ 1 行 CSV で追記できる。
- 記録は `tcyb monitor`（TUI）を開いているかどうかに左右されない。
- 既存の `chatters.csv`（`show-chatters` の出力）の末尾に続けて追記しても、1 つの CSV として読める。
- 記録を有効にしなければ、`read-chat` の挙動は従来と変わらない。

## 非ゴール

- コメント・通知の記録。
- `tcyb monitor`（TUI）側でのファイル書き込み、および TUI の表示変更。
- `show-chatters` の挙動・出力書式の変更。
- 出力形式の追加（JSON 等）、ファイルのローテーション、変化検出（前回と同じ一覧のときの抑制）。
- 配信口のプロトコル変更（メッセージ型・版の変更）。
- 取得に失敗した周期の記録（失敗は従来どおり接続状態とログに出す）。

## 受入基準

### 設定

- [ ] `[monitor]` にログの出力先ファイルパスを書く設定キーがある。省略時は何も記録しない。
- [ ] 設定キーに相対パスを書くと、`read-chat` を起動したカレントディレクトリ基準で解決される。絶対パスはそのまま使われる。
- [ ] 出力先が設定されているのに `monitor.enabled = false` のとき、`read-chat` は何が矛盾しているかを示すエラーで起動を中止する。
- [ ] 出力先のファイルを追記モードで開けない（親ディレクトリが無い・権限が無い等）とき、`read-chat` はその理由を示すエラーで起動を中止する。
- [ ] 設定ファイルの雛形（初回起動時に生成されるテンプレート）の `[monitor]` にこのキーがコメント付きで載っている。

### 記録

- [ ] 視聴者一覧の周期取得が成功するたびに 1 行が追記される。取得に失敗した周期は行を追記しない。
- [ ] 各行の書式は `show-chatters` の出力と同一である: `YYYY-MM-DD HH:MM:SS` のローカル時刻、カンマ、`channel` と `username` を除いた login 名を昇順にカンマ区切り。除外後に 0 人でも行末のカンマは省略しない。
- [ ] 同じ視聴者一覧を `show-chatters` と `read-chat` のログが書いたとき、タイムスタンプを除いて行が一致する。
- [ ] 1 行ごとに書き込みが flush され、途中で `read-chat` が落ちてもそれまでの行はファイルに残る。
- [ ] 既存ファイルがあれば末尾に追記し、無ければ作成する。既存の内容は消さない。
- [ ] 記録を有効にしても、配信口へ流れる視聴者一覧・接続状態・コメント・通知は従来と同じである。

### 稼働中の失敗

- [ ] 稼働中に行の書き込みに失敗しても、`read-chat` は終了せず、読み上げ・配信・次の周期の取得と記録を続ける。
- [ ] 書き込みの失敗は、理由とともに警告ログに出る。

### テスト

- [ ] 行の書式（タイムスタンプ・除外・昇順・行末カンマ）が、ネットワークに依存しないテストで検証されている。
- [ ] 取得成功時に行が追記され、取得失敗時に追記されないことが、ネットワークに依存しないテストで検証されている。
- [ ] 設定の矛盾（出力先あり・`enabled = false`）と、開けないパスで起動が中止されることがテストで検証されている。
- [ ] 書き込み失敗後もループが続くことがテストで検証されている。

### ドキュメント

- [ ] `tcyb/README.md` の `[monitor]` の設定例に新キーが載り、記録の書式が `show-chatters` と同じである旨と、`show-chatters --interval` の並走が不要になる旨が書かれている。
- [ ] `tcyb/README.md` に、稼働中の書き込み失敗では `read-chat` が止まらず警告ログに出ることが書かれている。
