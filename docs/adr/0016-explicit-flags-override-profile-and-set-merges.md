# 0016. 設定値は「明示フラグ > プロファイル > 既定」で解決し、profile set はマージ更新にする

- Status: Accepted
- Date: 2026-07-26
- Related: [vstc_cli プロファイル spec](../superpowers/specs/2026-07-26-vstc-cli-profiles-design.md), [ADR-0015](0015-single-profiles-toml-in-os-user-config-dir.md)

## Context

プロファイルを導入すると、同じ値（host / port / config_path）を指定する経路が「プロファイル」「コマンドラインの明示フラグ」「組み込み既定値」の 3 つになる。競合したときにどれを採るかを決める必要があった。

同時に `profile set` にも同じ形の曖昧さがある。既存プロファイルに対して一部のフラグだけを渡したとき、それを**部分更新**と読むか、**そのプロファイルの完全な定義**と読むか。

トレードオフは明示性と利便性の間にある。プロファイルを黙って上書きできると「どこへ送ったか」がコマンドラインだけからは分からなくなり、誤送信の余地が生まれる。一方、上書きを禁じると「保存済みの宛先の、ポートだけ変えて 1 回試す」ができず、その都度プロファイルを作るか全フラグを手打ちすることになる。

## Decision

**実行時**は「組み込み既定 → プロファイル → 明示フラグ」の順に後勝ちで解決する。`--profile` を土台に `--host` / `--port` / `--config-path` の明示フラグが個別に勝ち、上書きしなかったフィールドはプロファイルの値が残る。`--profile` と明示フラグの併用は許可する。上書きはメモリ上の解決だけで、プロファイルファイルには一切書き戻さない。

**`profile set`** は渡されたフィールドだけを更新するマージ更新にする。指定しなかったフィールドは既存の値を保持し、既定値に戻したりクリアしたりしない。

既定プロファイルの概念は導入しない。`--profile` を省略した実行は常に組み込み既定（`localhost:8080`）を使い、プロファイルファイルを読まない。

## Alternatives rejected

- **`--profile` と明示フラグの併用を禁止（競合はエラー）** — 「どの値が使われたか」が一意に決まる明快さはあるが、ワンショットの宛先変更にプロファイル作成を強いる。CLI の一般的な期待（明示引数が設定ファイルに勝つ）にも反する。
- **`profile set` を全置換にする** — 「set = そのプロファイルの定義」という意味が明確になるが、ポートだけ直したいときに host と config_path を毎回打ち直す必要があり、打ち漏らしが黙って値を消す事故につながる。破壊的な既定より保存的な既定を選ぶ。
- **既定プロファイルを持ち、`--profile` 省略時に自動適用する** — タイプ量は最も減るが、`vstc_cli pause` という同じコマンドが、いつどこで設定したか分からない既定によって別のインスタンスへ届く。誤送信は「止まらないはずの読み上げが止まる」形で現れ、原因が見えにくい。宛先は常にコマンドラインから読み取れる状態を優先する。
- **明示フラグ指定時にプロファイルへ自動保存する** — 「最後に使った設定」が育つ利便性はあるが、一時的な試行がプロファイルを恒久的に書き換える。保存は `profile set` に限定し、実行と保存を分離する。

## Consequences

`vstc_cli pause --profile main --port 8080` のようなワンショット上書きが書け、`profile set main --port 20000` が他フィールドを保たれる形で通る。プロファイル未指定の実行はプロファイルファイルの存在に依存しないため、ファイルが無い環境でも全コマンドが動く。

一方、`--profile` を省略すると保存済みプロファイルがあっても使われないため、常に `--profile` を打つ必要がある。この摩擦は意図したもので、宛先が明示的に読める状態と引き換えにしている。もし将来この摩擦が実運用で重すぎると分かったら、本 ADR を supersede して既定プロファイルを再評価する（その際は「現在の解決結果を表示する」手段の併設を条件とする）。

また `profile set` がマージである以上、フィールドを未設定に戻す手段が無い。当面は `profile remove` してから作り直す運用とし、必要になったらクリア用のフラグを別途検討する。
