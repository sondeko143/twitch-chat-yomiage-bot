# vstc_cli プロファイルの既定チェーン

## 問題

`vstc_cli send` は毎回、操作チェーンを位置引数で全部書く必要がある。同じ入力を複数の宛先へ流す構成（例: 文字起こしした結果を、無翻訳・英訳・露訳の 3 系統に分けてそれぞれ別ホストの字幕へ送る）では、系統ごとにホップの並びを書き分けた長いコマンドを、実行のたびに打ち直すことになる。

プロファイルには host / port / config_path しか保存できないため、この「よく使うチェーンの組」を保存しておく場所が無い。

さらに現状の CLI は 1 回の送信で 1 チェーンしか送れない。proto の `Command.chains` は複数チェーンを表現できるのに、その表現力に到達できていない。

## ゴール

- よく使うチェーンの組を、名前付きプロファイルに**複数チェーン**として保存できる。
- 保存したチェーンの追加・削除・確認が CLI だけで完結する。
- `send` で操作を書かなかったとき、プロファイルに保存したチェーンが送信される。
- 複数チェーンが 1 回の送信でまとめて宛先へ届き、テレメトリ上も 1 回の入力として追跡できる。
- チェーンを構成する route 文字列を、送信先とパラメータが読み取りやすい簡潔な記法で書ける。

## 非ゴール

- 保存せずにその場で複数チェーンを指定する CLI フラグ。1 チェーンで足りる場合は従来どおり `send` の位置引数で書く。
- 保存済みチェーンの並び替え・チェーン内の 1 ホップだけの編集。追加・削除・確認の 3 操作のみを提供する。
- `set_filters` / `ping` を route 文字列から指定できるようにすること。
- チェーン内の宛先から gRPC 接続先（host / port）を推論すること。接続先は従来どおり既定 → プロファイル → 明示フラグで解決する。
- 既定プロファイルの概念（`--profile` 省略時に特定プロファイルを自動適用する仕組み）。
- `vstc_gui` および `tcyb` の複数チェーン対応。

## 受入基準

### チェーンの保存と管理

- [ ] `vstc_cli profile chains add <NAME> <ROUTES>...` が、渡した route 列を 1 本のチェーンとして当該プロファイルの末尾に追加する。
- [ ] `vstc_cli profile chains show <NAME>` が、保存済みチェーンを 1 から始まる連番つきで、各チェーンのホップ順が読み取れる形で表示する。
- [ ] 保存済みチェーンが 0 本のとき、`profile chains show` は追加方法を案内して正常終了する（エラーにしない）。
- [ ] `vstc_cli profile chains del <NAME> <INDEX>` が、`profile chains show` の表示する連番で指定したチェーンを削除する。
- [ ] 範囲外の連番を `del` に渡した場合、現在の本数を含むエラーになり、保存内容は変わらない。
- [ ] `add` に渡した route 列に解釈できない要素が 1 つでもあると、エラーになり、チェーンは保存されない。
- [ ] `add` / `del` / `show` に未登録のプロファイル名を渡した場合、登録済みプロファイル名を含むエラーになる（未登録名で新規プロファイルが作られることはない）。
- [ ] 最後の 1 本を `del` した後のプロファイルは、チェーンを一度も保存していないプロファイルと同じ状態になる。
- [ ] チェーンは既存のプロファイルと同じ単一 TOML ファイルに、同じプロファイル名の下へ保存される。
- [ ] `vstc_cli profile list` が、各プロファイルの保存済みチェーン本数を表示する。未保存のプロファイルは未設定と分かる形で表示される。
- [ ] チェーンを保存していないプロファイルは、TOML ファイル上にチェーンの項目を持たない。

### 送信

- [ ] `send` に位置引数の操作を渡した場合、その操作だけが送信され、プロファイルの保存済みチェーンは送信されない。
- [ ] `send` に位置引数の操作を渡さず、`--profile` で指定したプロファイルにチェーンが保存されている場合、保存済みチェーンがすべて送信される。
- [ ] 保存済み N 本のチェーンを送信するとき、宛先は N 本すべてを含む 1 つのコマンドを 1 回だけ受け取る（チェーンごとに分割送信しない）。
- [ ] N 本のチェーンは同一の入力（テキスト / 音声 / file_path / filters）と同一の trace_id を共有する。
- [ ] `send` に位置引数の操作が無く、保存済みチェーンも解決できない場合、位置引数と保存の両方の指定方法を案内するエラーになり、送信は行われない。
- [ ] プロファイルに保存された route 文字列が解釈できない場合、プロファイル名・何本目のチェーンか・該当する route 文字列を含むエラーになり、送信は行われない。
- [ ] `--host` / `--port` / `--profile` による接続先の解決は、チェーンを送る場合も従来と同じ順序で行われる。

### route 文字列の記法

- [ ] `//<HOST>:<PORT>/<OP>?<QUERY>` 形式の route が、宛先・操作・パラメータつきの 1 ホップとして解釈される。
- [ ] `<OP>?<QUERY>` 形式（宛先を書かない）の route が、宛先なしの 1 ホップとして解釈される。
- [ ] 従来の `o:/<OP>` および `o://<HOST>:<PORT>/<OP>` 形式の route が、引き続き同じ意味で解釈される。
- [ ] 上記の記法は `profile chains add` と `send` の位置引数の双方で同じように解釈される。
- [ ] 文字起こし操作を route 文字列から指定できる。

### ドキュメント

- [ ] `vstc_cli/README.md` に、チェーンの追加・削除・確認の使用例と、保存された TOML の記述例が記載されている。
- [ ] `vstc_cli/README.md` に、`send` が位置引数の操作と保存済みチェーンのどちらを送るかの規則が記載されている。
