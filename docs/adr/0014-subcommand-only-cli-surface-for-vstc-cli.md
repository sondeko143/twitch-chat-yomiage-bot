# 0014. vstc_cli を全面サブコマンド化し従来の位置引数フォームを廃止する

- Status: Proposed
- Date: 2026-07-26
- Related: [vstc_cli プロファイル spec](../superpowers/specs/2026-07-26-vstc-cli-profiles-design.md)

## Context

`vstc_cli` は可変長の位置引数 `[OPERATIONS]...` に `o:/tts?spd=1.1` 形式の操作文字列を並べるフラットな CLI だった。ここへ `pause` / `resume` / `reload` / `profile` を足すと、clap は先頭トークンをサブコマンド名として解釈しようとするため、位置引数リストとサブコマンドが同一階層で共存する曖昧な文法になる。

操作文字列は必ず `o:/…` 形式でサブコマンド名と字面が衝突しないため、「既知のサブコマンド名に一致したときだけサブコマンド」という共存も技術的には可能だった。つまりこれは文法上の必然ではなく、互換性と表面の一貫性のどちらを取るかという選択である。

`vstc_cli` は `publish = false` のワークスペース内バイナリで、利用者は開発者自身に限られる。

## Decision

CLI の最上位を**サブコマンドのみ**にする。従来の位置引数フォームは `send` サブコマンドへ移し、`vstc_cli 'o:/tts' -t "hi"` は動かなくなる（破壊的変更）。`send` / `pause` / `resume` / `reload` / `profile` の 5 つを最上位に置き、接続オプション（`--profile` / `--host` / `--port`）は clap の `flatten` で `profile` を除く全サブコマンドに共通適用する。`vstc_cli/README.md` の使用例を新フォームへ更新する。

## Alternatives rejected

- **互換維持（既定＝従来フォーム、既知の名前だけサブコマンド）** — 既存の呼び出しがそのまま動く利点はあるが、`--help` に「位置引数もサブコマンドも取る」曖昧な表面が残り、将来サブコマンドを足すたびに「その名前で始まる操作文字列は無いか」を確認する暗黙の制約を負う。clap 側も特殊設定を要し、正しく効いているかを守るテストが増える。利用者が開発者のみで移行コストが小さい以上、この負債は割に合わない。
- **互換維持＋`send` エイリアスの併設** — 上記の欠点をすべて引き継いだうえ、同じ操作に 2 つの書き方が生まれてドキュメントとテストが二重になる。移行期間を必要とするほどの利用者がいない。
- **`pause` 等を `send` のフラグにする（`send --pause`）** — 最上位の表面は変えずに済むが、`pause` は操作チェーンを取らない別種の呼び出しであり、`send` の引数（`--wav` / `--filters` / `[OPERATIONS]`）と意味的に排他になる。排他性を clap の conflict 定義で表現し続けるより、別サブコマンドの方が素直。

## Consequences

`--help` がコマンドごとに関連オプションだけを見せるようになり、`pause` / `resume` / `reload` が操作文字列の記法を知らなくても打てる。サブコマンド固有の引数（`reload --config-path` 等）を、他のコマンドの表面を汚さずに追加できる。

一方、手元のシェル履歴・スクリプト・エイリアスに残る従来形式は `send` を足す書き換えが必要になる。破壊的変更なので、README の更新は実装と同一 PR で必須とする。将来もし外部利用者が生まれるなら、そのときは互換シムではなくバージョン境界で扱う。
