# vstc_cli プロファイルと pause/resume/reload サブコマンド

## 問題

`vstc_cli` は操作チェーンを URL 風文字列（`o:/tts?spd=1.1`）で組み立てて送るフラットな CLI しか持たない。proto には `Pause` / `Resume` / `Reload` が定義済みで `vstc` の変換表にも載っているのに、これらを使うには毎回 `'o:/pause'` のような文字列を手で書く必要がある。

さらに宛先（host/port）とリロード対象の設定ファイルパスは毎回コマンドラインで指定するしかない。複数の vstreamer-tool インスタンスを使い分けると、同じ長い引数列を繰り返し打つことになり、打ち間違えた宛先へ送る事故も起きる。

## ゴール

- `pause` / `resume` / `reload` を専用サブコマンドとして直接実行できる。
- 宛先（host / port）とリロード設定パス（config_path）を**名前付きプロファイル**として OS 標準のユーザー設定ディレクトリへ保存できる。
- プロファイルは CLI から作成・更新・一覧・削除できる。
- 各サブコマンドはプロファイル名を指定して実行でき、必要なら個別の値だけをその場で上書きできる。
- プロファイルを一切使わなくても、従来と同じ操作チェーン送信が行える。

## 非ゴール

- 既存の位置引数フォーム（`vstc_cli 'o:/tts' -t "hi"`）の互換維持。全面サブコマンド化に伴い `send` サブコマンドへ移行する。
- `Transcribe` / `Translate` / `Subtitle` / `Tts` / `Vc` / `Playback` / `SetFilters` / `Ping` / `Forward` の専用サブコマンド化。これらは引き続き `send` の操作チェーンで指定する。
- プロファイルへの認証情報・シークレットの保存。保存対象は host / port / config_path のみ。
- 既定プロファイルの概念（`--profile` 省略時に特定プロファイルを自動適用する仕組み）。
- `vstc_gui` のプロファイル対応。
- プロファイルファイルの手編集を支援する `profile edit` / `profile show` 等の追加操作。

## 受入基準

### サブコマンド

- [ ] `vstc_cli --help` に `send` / `pause` / `resume` / `reload` / `profile` の 5 サブコマンドが表示される。
- [ ] `vstc_cli send <OPERATIONS>... -t <TEXT>` が、従来の位置引数フォームと同じ内容のコマンドを送信する（`--wav` / `--file-path` / `--filters` も従来どおり指定できる）。
- [ ] `vstc_cli pause` が `Pause` 単独の操作チェーンを送信する。`resume` は同様に `Resume` を送信する。
- [ ] `vstc_cli reload` が `Reload` 単独の操作チェーンを、解決された設定パスを `file_path` に載せて送信する。
- [ ] `send` / `pause` / `resume` / `reload` のいずれでも `--profile` / `-H, --host` / `-p, --port` を指定できる。

### プロファイルの保存と管理

- [ ] `vstc_cli profile set <NAME> [--host <HOST>] [--port <PORT>] [--config-path <PATH>]` がプロファイルを保存する。
- [ ] `profile set` は指定したフィールドだけを更新し、指定しなかったフィールドは既存の値を保持する。
- [ ] `vstc_cli profile list` が保存済みプロファイルを名前順に、名前・host・port・config_path つきで表示する。未設定のフィールドは未設定と分かる形で表示される。
- [ ] 保存済みプロファイルが 0 件のとき、`profile list` は作成方法を案内して正常終了する（エラーにしない）。
- [ ] `vstc_cli profile remove <NAME>` が該当プロファイルを削除する。存在しない名前を指定した場合はエラーになる。
- [ ] プロファイルは OS 標準のユーザー設定ディレクトリ配下の単一 TOML ファイルに保存される。
- [ ] 保存先ディレクトリを環境変数 `VSTC_CONFIG_DIR` で上書きでき、上書きした場合はそのディレクトリ配下のファイルが読み書きされる。
- [ ] 保存先ディレクトリが存在しない場合、`profile set` はディレクトリを作成してから書き込む。
- [ ] プロファイルファイルの書き込みは、書き込み途中で中断されても既存の内容が壊れない方法で行われる。

### 値の解決

- [ ] `--profile` も `--host` / `--port` も指定しない場合、宛先は `localhost:8080` になる。
- [ ] `--profile <NAME>` を指定した場合、そのプロファイルの host / port が既定値より優先される。
- [ ] `--host` / `--port` を明示した場合、プロファイルの対応する値より優先される。プロファイルの他のフィールドは影響を受けない。
- [ ] `reload` の設定パスは `--config-path` がプロファイルの `config_path` より優先される。
- [ ] `reload` で設定パスがどちらからも解決できない場合、その旨を伝えるエラーになり、送信は行われない。
- [ ] 存在しないプロファイル名を `--profile` に指定した場合、保存済みプロファイル名を含むエラーになり、送信は行われない。
- [ ] `--profile` を指定しないコマンドは、プロファイルファイルが存在しなくても正常に動作する。
- [ ] プロファイルの `config_path` は `reload` の設定パス解決にのみ使われ、`send --file-path` には影響しない。
