# tcyb monitor（配信モニタ TUI）と通知読み上げの統一

## 問題

配信中に「いま誰がいるか」「どんなコメントが流れたか」「どんな通知（フォロー・レイド・サブスク等）が来たか」を手元で一望する手段がない。

- 視聴者は `show-chatters` で取れるが、1 行 CSV を出すだけで、コメントや通知と並べて見られない。また先頭 1 ページ（100 人）しか取得しないため、それを超えると欠ける。
- コメントと EventSub 通知は `read-chat` プロセスの内部でしか流れておらず、stderr のログ以外に外から観測する経路がない。
- EventSub は `channel.follow` しか購読しておらず、レイドやサブスク等の通知はそもそも受け取っていない。
- 通知の読み上げはフォロー専用の単一テンプレート（`greeting_template`）にハードコードされており、他の通知種別へ広げられない。

## ゴール

- `read-chat` が、受け取ったコメント・EventSub 通知・視聴者一覧を、同一マシン上の別プロセスへ配信できる。
- 新サブコマンド `tcyb monitor` が、それらをリアルタイムに表示する TUI として動く。
- TUI は `read-chat` の起動後いつ開いても、その `read-chat` が起動してからの直近のコメント・通知を遡って表示できる。
- TUI の起動・終了・異常終了が、`read-chat` の読み上げに影響しない。
- 通知の読み上げを、通知種別ごとにテンプレートを設定する単一の仕組みに統一する（フォロー読み上げもこの仕組みに載せ替える）。

## 非ゴール

- コメント・通知・視聴者の永続化（`read-chat` 終了をまたいだ履歴）。
- 同一マシン外（LAN・インターネット）からの接続、および IPC の認証。
- TUI からの操作（コメント投稿・BAN・読み上げの停止等）。TUI は閲覧専用。
- TUI 上の検索・フィルタ。
- 配信者本人のトークンを要する EventSub 購読（`channel.subscribe` / `channel.cheer` 等）。
- コメント読み上げ（チャット本文の読み上げ・翻訳）の挙動変更。
- `show-chatters` サブコマンドの出力書式の変更。
- GUI（`vstc_gui`）からの利用。

## 受入基準

### 配信（read-chat 側）

- [ ] 設定で IPC を有効にしない限り、`read-chat` は待受ポートを開かず、従来どおり動く。
- [ ] IPC を有効にすると、`read-chat` は `127.0.0.1` のみで待ち受け、それ以外のアドレスからは接続できない。
- [ ] IPC の待受に失敗しても（ポート使用中等）、警告ログを出して読み上げは継続する。
- [ ] 接続直後のクライアントは、まず直近のコメント・通知（保持件数は設定可能、上限超過分は古い順に捨てる）・最新の視聴者一覧・接続状態のスナップショットを受け取り、以降は新着を 1 件ずつ受け取る。
- [ ] クライアントの受信が遅れて取りこぼしが生じた場合、クライアントは再びスナップショットを受け取り、表示が欠落したまま継続しない。
- [ ] クライアントが接続していない・受信が遅い・切断した、のいずれでも、コメントと通知の読み上げは遅延・停止しない。
- [ ] 配信メッセージにはプロトコル版が含まれ、版の異なる `monitor` は非互換である旨を表示する。
- [ ] 視聴者一覧は設定した間隔で更新され、100 人を超える場合も全員が含まれる。
- [ ] 視聴者一覧の取得に失敗した場合（権限不足等）、その旨が接続状態としてクライアントへ届き、次の周期で再試行する。

### EventSub 通知

- [ ] `channel.follow` に加え、`channel.raid` と `channel.chat.notification` を購読する。
- [ ] 購読していない種別も含め、受け取った通知は種別を問わずクライアントへ配信される（未知の種別でも捨てない）。
- [ ] 必要なスコープ（`user:read:chat`）が `auth-code` で要求され、README に再認可が必要な旨が記載されている。

### 通知読み上げの統一

- [ ] 設定に、通知種別（`type`、任意で `notice_type`）ごとの読み上げテンプレートを複数書ける。
- [ ] 通知を受けると、`type` と `notice_type` が一致するテンプレートで読み上げる。`notice_type` まで一致するものがあればそれを、無ければ `notice_type` 未指定のものを使う。
- [ ] どのテンプレートにも一致しない通知は読み上げない。
- [ ] テンプレート中の `{field}` は通知イベントの同名フィールドで、`{a.b}` はネストしたフィールドで置換され、`{{` / `}}` はそれぞれ `{` / `}` として出力される。
- [ ] 存在しないフィールドを参照したプレースホルダは空文字に置換され、警告ログが出る。
- [ ] 旧設定キー `greeting_template` が設定に残っていると、`read-chat` は新形式への書き換え方を示すエラーで起動を中止する。
- [ ] フォローの読み上げは、新形式のテンプレート設定でのみ行われる。
- [ ] README に新形式の設定例があり、レイドを `channel.raid` と `channel.chat.notification` の両方に書くと二重に読み上げられる旨の注意がある。

### monitor（TUI）

- [ ] `tcyb monitor` で、コメント欄・通知欄・視聴者欄（人数付き）・接続状態行からなる画面が表示される。
- [ ] 接続状態行に、`read-chat` との接続有無、IRC / EventSub の接続状態、視聴者一覧の最終更新時刻（または取得失敗）が表示される。
- [ ] 視聴者欄で、`monitor` 起動後に新たに一覧へ現れた視聴者が区別して表示される。
- [ ] `read-chat` が動いていない状態で起動しても終了せず未接続と表示し、`read-chat` の起動・再起動に追従して自動で再接続する。
- [ ] `q` で終了し、`Tab` で欄の切替、`↑` `↓` `PgUp` `PgDn` でスクロール、`End` で最新への追従に戻る。
- [ ] 終了時および panic 時に端末の表示状態が元に戻る。

### テスト

- [ ] 保持件数の上限・取りこぼし時のスナップショット再送・配信メッセージの直列化往復が、ネットワークに依存しないテストで検証されている。
- [ ] テンプレートの選択規則と置換規則（ネスト・欠落・波括弧エスケープ）がテストで検証されている。
- [ ] 視聴者一覧のページングと、新規視聴者の判定がテストで検証されている。
- [ ] ローカルに IPC サーバを立ててクライアントを接続し、スナップショット→新着の順で届くことが検証されている。
- [ ] TUI の描画が、端末に依存しないテストで検証されている。
