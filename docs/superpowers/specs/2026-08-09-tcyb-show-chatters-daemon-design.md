# tcyb show-chatters の周期取得（常駐）

## 問題

`tcyb show-chatters` は Get Chatters を 1 回叩いて 1 行の CSV を出力し、終了する。配信中の視聴者の推移を時系列で残したい場合、外部のスケジューラから短い間隔で起動を繰り返すことになるが、これには次の難がある。

- 起動のたびにトークン DB の読み込みとチャンネル ID の解決（Get User）が走るため、1 サンプルあたり Twitch API を 2 回叩く。
- Windows のタスクスケジューラは秒単位の反復を素直に表現できない。
- トークンのリフレッシュ状態がプロセス内に残らず、毎回ディスクから読み直される。

「N 秒ごとにサンプリングし続ける」という用途が、コマンド自身では表現できない。

## ゴール

- `show-chatters` を、N 秒ごとに取得を繰り返す常駐モードで起動できる。
- 常駐中の 1 サンプルあたりの Twitch API 呼び出しは Get Chatters のみで済む。
- 常駐中の出力は一発実行と同じ 1 行 CSV で、シェルのリダイレクトでそのままファイルへ追記できる。
- 常駐は Ctrl+C で正常終了できる。
- 引数を足さずに実行した従来の一発実行は、挙動が変わらない。

## 非ゴール

- プロセスのバックグラウンド化・デタッチ・PID ファイル・Windows サービス登録。バックグラウンド実行と自動起動は OS 側の仕組みに委ねる。
- 失敗時の自己回復（リトライ・バックオフ・自動再起動）。トークン失効時のリフレッシュを除く。
- 出力先ファイルの指定、ファイルのローテーション、出力形式の追加（JSON など）。
- 変化検出（前回と同じ chatters のときに出力を抑制する）。
- `read-chat` など他サブコマンドの常駐化、および常駐モード同士の同時実行。
- 取得結果の DB / ストアへの保存。

## 受入基準

### 一発実行（後方互換）

- [ ] 間隔を指定せずに `show-chatters` を実行すると、従来どおり 1 行出力して終了する。
- [ ] 一発実行時の出力書式・並び順・除外規則が従来と変わらない。

### 常駐モード

- [ ] 間隔に N 秒を指定して `show-chatters` を実行すると、起動直後に 1 行出力し、以降 N 秒ごとに 1 行出力し続ける。
- [ ] 常駐中の各行の書式は一発実行時と同じである（`YYYY-MM-DD HH:MM:SS` に続けて chatters の login 名をカンマ区切り、昇順ソート、設定の `channel` と `username` は除外）。
- [ ] 間隔に 0 を指定した場合、指定が不正である旨のエラーになり、Twitch API は 1 回も呼ばれない。
- [ ] 1 回の取得に N 秒以上かかった場合でも、実施できなかった分の取得は溜まらず、遅れを取り戻すためのまとめ発火は起きない。
- [ ] 常駐中は、チャンネル ID の解決とトークン DB の読み込みが起動時の 1 回のみで、以降の各取得では行われない。

### 停止とエラー

- [ ] 常駐中に Ctrl+C を送ると、停止した旨をログに残して終了コード 0 で終了する。
- [ ] 常駐中に Twitch API が 401 を返した場合、トークンをリフレッシュして同じサンプルの取得を再試行し、常駐は継続する。
- [ ] 常駐中に 401 以外のエラーが返った場合、プロセスは非 0 の終了コードで終了する。

### テスト

- [ ] 出力行の組み立て（並べ替え・除外・タイムスタンプ付与）が、ネットワークに依存しないテストで検証されている。
- [ ] 間隔指定の有無と不正値の解釈が、ネットワークに依存しないテストで検証されている。

### ドキュメント

- [ ] `tcyb/README.md` の `show-chatters` に関する記述に、常駐モードの起動方法が記載されている。
- [ ] `tcyb/README.md` に、出力をファイルへ追記する運用例と、停止方法が記載されている。
- [ ] `tcyb/README.md` に、エラー時はプロセスが終了し自動再起動しないことが記載されている。
