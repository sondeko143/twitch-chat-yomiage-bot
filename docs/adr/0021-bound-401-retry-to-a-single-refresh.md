# 0021. トークンリフレッシュ後の 401 は再リフレッシュせず常駐を終了する

- Status: Accepted
- Date: 2026-08-09
- Related: [show-chatters 常駐 spec](../superpowers/specs/2026-08-09-tcyb-show-chatters-daemon-design.md), [ADR-0019](0019-foreground-only-daemon-for-show-chatters.md)

## Context

`with_token_refresh`（`tcyb/src/chat.rs`）は Helix API 呼び出しが 401 を返すたびにトークンをリフレッシュして同じ呼び出しをやり直す。リフレッシュ (`Store::update_tokens`) が失敗せずに完了し続ける一方で API が 401 を返し続けるケースでは、この再試行ループに上限も待機もなく、Helix エンドポイントとトークンエンドポイントの双方を無遅延で叩き続ける。

このケースは机上の空論ではない。README（`tcyb/README.md`）が明記するとおり、`auth-code` を対象チャンネルのモデレーター権限を持つ bot アカウントとは別のアカウントで認可すると、トークン自体は有効でも `moderator:read:chatters` スコープを欠いたまま発行される。この状態では API は恒久的に 401 を返し、リフレッシュはそのたびに成功する（トークン自体は更新できるため）ため、無制限リトライループに入る。

ADR-0019 は「一過性エラーを握りつぶして次の tick へ進む」代替案を、恒久的な失敗が沈黙故障になることを理由に既に却下している。無制限リトライも同じ性質の問題である。常駐がクラッシュも進行もせず高頻度リクエストだけを発し続けるため、外形的には「動いているように見える」まま無人記録が失敗し、かつ Twitch 側のレート制限や不正利用検知を誘発しうる。

## Decision

`with_token_refresh` はトークンリフレッシュを呼び出し 1 回につき最大 1 回だけ行う。

- ループ内に `refreshed: bool` を持ち、初期値は `false`。
- 401 を受け、まだリフレッシュしていなければ (`!refreshed`) リフレッシュして `true` にし、同じ呼び出しを再試行する。
- 401 を受け、既にリフレッシュ済みなら再リフレッシュせず、下層の `reqwest::Error` を運んだまま `bail!` する（非 401 エラーの既存経路と同じ形）。

根拠: トークンリフレッシュは 401 を解決するか、そもそも 401 の原因がトークンの鮮度ではなかったかのどちらかである。後者であれば何度リフレッシュしても状況は変わらないため、2 回目のリフレッシュに意味はない。

## Alternatives rejected

- **無制限リトライを維持する** — 本 ADR が解決しようとしている問題そのもの。スコープ不足のような恒久的な 401 で Helix とトークンエンドポイントを無遅延で叩き続け、レート制限や不正利用検知を誘発しうる。
- **指数バックオフを足す** — 恒久的な 401（スコープ不足）に対してはバックオフしても最終的に諦めない限り無駄打ちが続くだけで、問題の本質（いつ諦めるか）を解決しない。待機時間の上限・初期値・増加率という新たな非自明なパラメータも増える。
- **固定 N 回まで再試行する** — N の根拠が非自明であることは ADR-0019 が「連続失敗 M 回で終了する」を却下した理由と同じ。加えてトークンリフレッシュは「成功/失敗」の二値であり、同じリフレッシュ操作を何度繰り返しても結果が変わる理由がない（初回のリフレッシュが失敗ではなく成功しているのに 401 が続くケースが対象なので、回数を増やしても新しい情報は得られない）。1 回で十分かどうかを判断するのに複数回の実績は不要。

## Consequences

- スコープ不足など恒久的な 401 は、リフレッシュ 1 回の後に即座にプロセスを終了させる非 0 終了として現れる。ADR-0019 が定めた「非 401 エラーは握りつぶさずプロセスを終了させる」という方針と一貫する形になり、401 だけが特別扱いで無限に粘る非対称性が無くなる。
- 一過性の理由でリフレッシュ直後にもう一度だけ 401 が返るような稀なケース（例えばリフレッシュとほぼ同時に API 側でトークンが未反映）でも、常駐はリトライせずに終了する。従来の「401 は常駐を止めない」という直感に対する後退だが、実際にはトークン鮮度以外の理由で 401 が返るケースを覆っている以上、無制限に粘る方が誤り。
- `Store::user_id`（`tcyb/src/store.rs`）は本 ADR の対象外で、401 に対するリトライを一切持たない状態のまま残る。これは本 ADR が塞いだ「無制限リトライ」とは逆方向のギャップ（リトライが無さすぎる）であり、意図的に未着手とする。
